# Systems Plan

This document defines the six systems needed to turn the Archive from a case launcher into a full experience.

## 1. Archive Path Types

### Purpose

Show what kind of Archive the player is building through repeated decisions.

### Current State

Basic path labels exist in the Archive Hub:

- Unformed Archive
- Careful Archive
- Exposed Archive
- Sheltered Archive
- Broadcast Archive
- Hidden Archive
- Living Archive
- Watched Archive
- Fractured Archive

### Needed Next

- Add more explicit "why this path" meter math.
- Make future cases react to the path.

### Implemented

- Path description panel.
- Strength and risk copy.
- Forecast alignment with current path.

### Player Experience

The player should feel: "My choices are becoming a philosophy."

## 2. Evidence Types

### Purpose

Make artifacts feel varied, tactile, and system-specific.

### Current State

Evidence cards show source-type labels and icons.

The Archive Hub now has Evidence Vault cards with type, risk, consent, reliability, why-it-matters text, and tags.

### Needed Next

- Track preserved evidence across cases.
- Tag evidence by reliability, consent risk, and mythic force.

### Player Experience

The player should feel: "I am collecting dangerous records, not just reading pages."

## 3. Witness Types

### Purpose

Make people and communities respond differently to the Archive.

### Current State

Witness Ledger shows consequence text after case choices.

The Archive Hub now has witness profile cards with type, stance, note, and potential lead.

### Needed Next

- Add witness profiles.
- Track trust/fear/hostility.
- Tie witnesses to future leads.

### Player Experience

The player should feel: "People remember how I handled previous truths."

## 4. Case Types

### Purpose

Keep each case structurally distinct.

### Current State

Case 001 is an identity/exit case.

Case 002 is a community/synthetic-care case.

Case 003 is planned as a market/care-labor case.

The Archive Hub now displays case type and what each case tests.

### Needed Next

- Define a case-type taxonomy.
- Use case type to vary mechanics, evidence, and ending pressure.

### Player Experience

The player should feel: "Each case tests a different part of the Network."

## 5. Consequence Types

### Purpose

Make Publish / Bury / Preserve change future conditions.

### Current State

Choices affect Archive meters, vault, witness ledger, and forecast.

The Archive Hub now displays consequence tags and next-lead lines per completed case.

### Needed Next

- Add path-specific case intros.
- Add consequence tags such as backlash, trust gain, lead unlocked, interference, false narrative.
- Make future cases display why they unlocked.

### Player Experience

The player should feel: "The Archive remembers what I did."

## 6. Mythos Force Types

### Purpose

Connect cases back to the larger Network Mythos.

### Current State

The Mythos Layer lists forces revealed by completed cases.

The Mythos Layer now has force cards with descriptions, patterns, and seen-in case tracking.

### Needed Next

- Add descriptions for each force.
- Show which cases revealed each force.
- Add pattern tracking across cases.

### Player Experience

The player should feel: "I am learning the hidden structure of the Network."

## Implementation Order

1. Archive Path Types
2. Consequence Types
3. Witness Types
4. Evidence Types
5. Mythos Force Types
6. Case Types
